# 검토 기록: Token Runway

## 기준과 범위

- 스킬: benjitaylor/skills, 커밋 `299140fafd08df55a9c234e610c3f64af3f45531`
- Gold: `dark-hero`. 표면의 명암, 한 가지 강조색, 프레임 구조에서 시작했다.
- 바꾼 것: 배포 목록을 Token Runway의 네 화면으로 교체하고, 작은 시안은 콘텐츠 중심 카드로 다시 구성했다.
- 정지 시안이며 타임라인·커서·자동 재생은 없다. 정지 화면에 해당하는 `--still --gate`를 적용했다.
- 제품 소개용 시안과 실제 앱 미리보기는 별도다. 실제 앱 컴포넌트에는 데이터 생략이나 크롭을 적용하지 않았다.

## 촬영

- 일반: 600×440 디자인 크기, 대시보드·히스토리·알림·설정 4개.
- 작은 화면: 390px 뷰포트 안 358px 디자인 크기, 화면별 높이를 조정한 4개.
- 테마: 정지 시안은 다크. 실제 앱은 다크 960×800, 라이트 720×480에서 확인.
- 촬영 도구: 스킬의 `film.mjs`, 설치된 Chrome의 별도 헤드리스 세션.
- 실제 앱 확인: Aside의 샘플 IPC 환경. 실제 네이티브 앱 전체 동작 검증은 아니다.

## 검사와 수정

최종 정지 시안 8개에 적용한 게이트:

`rehearsal passed (necessary, not sufficient: references/verify.md and the fresh eye in review.md still stand)`

- 프레임 가장자리의 애매한 잘림 → 창 너비와 작은 화면의 카드 구도를 조정.
- 작은 알림의 간격 → kit의 Thread/Bubble로 교체하고 요청 라벨 간격 조정.
- 작은 히스토리의 보조 라벨 잘림 → 시안 높이를 늘려 실내용을 보존.
- 독립 시각 검토: 하단 공백, 차트의 단위·날짜 누락, 설정 설명의 위계 지적 → 구도·축 표기·보조 명도 조정.
- 재검토: 주간 차트 피크 날짜가 끝 날짜처럼 읽힘 → 축의 끝 날짜와 실제 피크 날짜를 분리.
- 기준 예제 원본의 정지 촬영에는 자체 정렬 경고가 있었다. 원본의 무결성을 검증했다고 주장하지 않는다.

## 실제 앱에 반영

- 잔여율 36px, 보조 수치 21px, 히스토리 합계 28px로 강조 우선순위를 분리.
- 사용량 차트는 키 컬러인 주황 단색으로, 잔여량 바는 현재 구간의 상태색 하나로 표시.
- 히스토리 막대와 라벨을 grid의 별도 영역으로 배치해 큰 막대들이 같은 높이로 줄어드는 문제 수정.
- 대시보드 사용 흐름에 단위, 윈도우 시작·현재 시점 라벨 추가.

## 확인

- 앱 `pnpm build` 통과.
- `pnpm check:i18n` 통과: ko/en 각 265키.
- Stageshow `npm run typecheck`, 대상 예제 CSS 클래스 충돌 검사 통과.
- 실제 히스토리에서 12K~30K 예시의 막대 높이 22.4~56px로 값에 비례함을 확인.
- 실제 앱 네 화면을 최소 너비에서 확인했으며 가로 넘침은 없었다.

확인하지 않은 것: 애니메이션·재생/중단·루프, 모바일 앱 동작, 실제 계정 사용량과 알림, 네이티브 WebView의 운영 환경 전체 흐름.
