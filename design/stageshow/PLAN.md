# Token Runway 디자인 검토

절차: [benjitaylor/skills · Stageshow](https://github.com/benjitaylor/skills/blob/main/stageshow/SKILL.md)

## 화면과 초점

정지 시안으로 검토한다. 데스크톱 760px와 작은 검토 화면 358px에서 읽을 수 있게 구성한다.
실제 앱의 최소 창 너비는 720px이며, 358px 시안은 제품 소개용 구도다.
기준 예제는 `dark-hero`: 검은 바탕 위 표면의 명암, 한 가지 강조색, 일정한 행 간격을 따른다.

- 대시보드: 남은 사용량을 먼저 보고, 소진 속도와 예상 시간으로 판단한다.
- 히스토리: 기간 합계와 추세를 먼저 보고, 일평균과 피크는 보조로 읽는다.
- 알림: 프로젝트 → 요청 → 답변·대기 상태 순으로 읽는다.
- 설정: 항목명 → 설명 → 컨트롤 순으로 읽는다.

## 색상과 위계

오르카의 중립색 표면 구조에 캐치테이블 주황 `#ff3d00`을 키 컬러로 쓴다.
본문·작은 주황 글자는 밝은/어두운 테마에 맞춰 별도 명도를 사용한다.
장식용 다색 그라데이션을 없애고, 상태색은 상태 판단에만 사용한다.
큰 수치는 한 그룹에서 하나만 둔다. 나머지는 크기와 굵기를 낮춘다.

## 검증

1. 기준 예제를 촬영해 구도와 정보 밀도를 비교한다.
2. 네 화면의 정지 시안을 만들고 스킬의 `film.mjs --still --gate`로 검사한다.
3. 실제 앱은 샘플 데이터로 960px/720px, 다크/라이트를 확인한다.
4. 결과와 확인하지 않은 항목은 `REHEARSAL.md`에 남긴다.

홍보 시안의 생략·크롭 규칙을 실제 앱 데이터나 접근성 의미 구조에 적용하지 않는다.
